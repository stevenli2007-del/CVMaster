# CVMaster UI 设计与交互规范

状态：v0.1，CP1 前端实现基准（MVP 仅电脑端）  
目标：让 CVMaster 具有安静、可信、沉浸的深空观感，并让主场景确实是可实时互动的 3D 粒子空间。

## 1. 设计意图

CVMaster 把每段经历呈现为一颗星球，把证据呈现为围绕星球运行的碎片。星图负责让用户发现、整理和进入经历；侧栏负责完成输入、确认、生成等实际任务。

视觉情绪：深邃、清晰、克制、有生命感。要有高质量的空间感和精致光效，但保持信息可读，不能让星云、辉光、粒子或玻璃效果盖过工作内容。

## 2. 参考方向

- [Starbase](https://github.com/verycracked/starbase)：参考可旋转/缩放的 3D 星云、力导向布局、选中节点后的镜头聚焦与邻居连线。CVMaster 的节点语义是经历与素材，不照搬代码依赖图、控制方式或视觉装饰。
- [Atomic Globe](https://www.framer.com/marketplace/components/atomic-globe/)：参考粒子组装、拖拽旋转、光标附近的粒子反馈、帧率无关的运动，以及低端/移动设备和 `prefers-reduced-motion` 适配。
- 原型 HTML：参考深空底色、衬线斜体空状态标题、颜色编码碎片、右侧玻璃面板/移动底部面板和“Make a new star”入口。

只借鉴交互和视觉原则；不要复制受限组件源码、素材或品牌内容。实现保持 CVMaster 自有的布局、动效节奏和体验。

## 3. 页面构成

### 桌面端（≥ 900 px）

- 全屏 3D 星图作为背景主画布，覆盖可用视口；背景有很淡的靛蓝/紫色与青色星云，不使用明显的网格或面板边框分区。
- 左上角放轻量品牌与当前视图名称；品牌不抢主标题。
- 初次使用时，中央略偏上显示衬线斜体 `What happened?`，下一行短说明；底部中心放唯一高优先级按钮 `Make a new star`。
- 创建或打开经历后，右侧出现约 400–440 px 暗色玻璃面板。星图仍保留足够空间，打开的经历在自由区域中聚焦。
- 面板内优先呈现经历名称、一个大投放框和明确状态。不要一开始展示分类表单、复杂筛选器或多个同权重主按钮。

### 后续版本：移动端（< 900 px）

- 移动端不属于 MVP；以下内容只作为后续版本设计备忘，不应扩大 CP1 范围。
- 3D 星图仍是主视觉，横向滚动/页面滚动不能截断主要操作。
- 详情面板改为底部抽屉，初始高度约 55–65vh；支持关闭和适当的向上扩展。
- 保留触摸旋转、双指缩放和点按选择；抽屉打开时，将背景拖动手势限制在画布区域，避免与面板滚动冲突。
- 粒子数量和 DPR 下调。点击目标尺寸至少 44×44 CSS px。

## 4. 颜色、材质与字体

建议设计 token（实现可微调色值，但需保持角色语义）：

| Token | 建议值 | 用途 |
|---|---|---|
| `space-950` | `#04050D` | 主背景 |
| `space-900` | `#090D1D` | 远景云雾/面板底色 |
| `space-800` | `#10162B` | 面板高亮/输入框 |
| `text-primary` | `#E8ECFF` | 主要文字 |
| `text-muted` | `#8A93B8` | 次要说明 |
| `line-soft` | `rgba(160,175,255,.20)` | 玻璃边框/分隔 |
| `accent-violet` | `#8B83FF` | 主操作/星球光晕 |
| `accent-cyan` | `#67E8F9` | Web 链接碎片 |
| `accent-green` | `#86EFAC` | GitHub 碎片/已完成状态 |
| `accent-pink` | `#F9A8D4` | 图片碎片 |
| `accent-amber` | `#FCD34D` | 语音碎片/待确认提示 |

- 背景以几乎黑色海军蓝为主，星云采用低饱和、低不透明度、多层径向渐变。
- 文字对比优先；弱光效不用于正文底图。
- 空状态主标题使用有个性的衬线斜体（Georgia / Iowan Old Style 系统回退）；其他 UI 使用系统 sans-serif 或项目选定的可读字体。
- 玻璃面板：深色半透明背景、约 16–24 px backdrop blur、细边框和轻微内高光。控制透明度，确保面板文字对比度。
- 星球有明暗球体、外围柔和辉光、非常淡的薄环；不要做成写实 NASA 行星贴图风格。

## 5. 3D 星图规范

### 5.1 场景层次

从远到近建议按以下层组织：

1. 固定的 CSS 星云渐变背景。
2. 稀疏远景星尘：缓慢漂移、亮度轻微呼吸；MVP 电脑端约 250–320 点，具体按实测预算调整。
3. 轻微视差的中景粒子雾；避免全屏均匀撒点，需有疏密与深度变化。
4. 经历星球节点：发光球体、浅环、名称与素材数等 DOM label。
5. 素材碎片：小型发光菱形或几何点，分布在各自经历的倾斜轨道上。
6. 关联经历间的曲线连接与缓慢流动的少量光点。

保持相机有真实的透视与层次，但运动幅度克制；默认不把场景做成旋转地球，也不让星球像 UI 气泡一样贴在平面上。

### 5.2 星球语义

- 一个经历 = 一颗星球；名称是主要标签，素材数量是次要标签。
- 大小与光亮随素材数量渐进增强，需设置上下限，避免最活跃经历遮蔽其他经历。
- 初次进入时星球分散在可视区域，彼此有呼吸空间；新星球从一个小型凝聚光点形成。
- 已打开星球平滑移动至自由画布的视觉中心；侧栏打开后，画布中心要避让面板。
- 星球选中时提亮并呈现薄环/小范围强调；其他星球降低对比度，但仍可辨认和重新选择。
- 相关经历之间用弧线连接；没有可信相关性时不要自动连线。连接上最多少数几个慢速流动光点，不画满网状线。

### 5.3 碎片颜色编码

- 图片：粉色；GitHub：绿色；普通 Web 链接：青色；语音：琥珀色；笔记：近白色；其他文件：蓝紫色。
- 形状保持统一为小菱形/晶体，不靠颜色作为唯一识别方式；面板列表必须提供文字类型标签或图标。
- 素材加入后从输入/投放位置飞向所属星球，带短暂光迹；到达时星球轻微脉冲，碎片进入自己的椭圆倾斜轨道。
- 每颗星球的轨道有不同倾角、速度、半径与相位；轨道不能互相穿过到无法辨识，也不要持续快速旋转。
- 悬停/聚焦碎片时显示简洁 tooltip；MVP 电脑端不能依赖不可访问的 WebGL hover，需同步提供 DOM 状态。

### 5.4 实时交互

- MVP 电脑端使用鼠标拖拽旋转、滚轮缩放；平移仅在明确的拖拽手势或中键/修饰键下触发，避免抢走点选。触控手势属于后续版本。
- 单击/点按星球：选择并平滑聚焦，同时打开详情面板；再次点击空白或关闭按钮可退出。
- 指针附近：产生局部 Halo/Wake 式微光或轻微粒子偏移，力度小、衰减快；不要制造大面积爆炸或遮挡点击。
- 新建星球：由中央附近的一团散点聚合成星球，随后停在布局位置；动效围绕“用户创建”发生。
- 放入素材：碎片从投放源飞到星球，显示短暂环形脉冲；面板明确显示“AI is sorting it”及完成/失败状态。
- 空闲时：星尘缓慢漂移，星球/轨道以低频率变化，整体不应像屏保般持续抢注意。
- 相机过渡采用 ease-in-out，通常 500–900 ms；创建凝聚 700–1200 ms；素材飞行 450–900 ms。减少动态效果时直接切换或仅保留淡入淡出。

### 5.5 标签、命中与可访问性

- 星球名称、素材数量和选中状态使用 HTML/DOM overlay，而非画进不可访问的 Canvas/WebGL 纹理。
- 星球提供键盘可聚焦的对应 DOM 控件；方向键/Tab 可在节点间移动，Enter/Space 打开，Escape 关闭。
- 提供 `Reset view` 控件；如果旋转/缩放被打乱，用户能一键回到概览。
- 颜色之外还要有图标、短标签或形状差异；文字不能只依赖发光描边。
- `prefers-reduced-motion: reduce` 时关闭自动旋转、漂移、呼吸、飞行粒子和指针扰动；用户动作仍有明确即时反馈。

## 6. 侧栏与素材录入

- 面板顶部是可编辑的经历名和关闭控件。
- 主入口是一块明显的大投放区，文案：`Drop anything, AI sorts it`。支持粘贴链接、打字、图片/文件上传、拖放和按住说话；首次界面只给必要提示。
- 文本输入可用 `Enter` 提交、`Shift+Enter` 换行；也提供可见的提交动作以支持触屏与辅助技术。
- 语音按钮显示按住录音/松开发送/不可用状态；权限或浏览器不支持时提供可理解提示和文字替代。
- 每项素材列表简洁呈现类型、来源片段/文件名、处理状态与错误重试操作。
- 页面要区分空、正在处理、处理完成、失败、AI 不可用等状态，不用 toast 代替持久状态。
- CP1 的示例星球可以静态预置；投放区可接收用户临时输入并在浏览器内存中显示为预览碎片，以便演示飞入/环绕动效。必须持续清楚标注 `Preview only — not saved`；刷新、关闭面板或离开页面后预览内容即清空。
- CP1 不上传文件、不持久化任何输入、不抓取链接、不调用 AI，也不把预览描述为真实处理结果。拖入文件时仅显示文件名和类型，不读取或发送文件内容。

## 7. 主操作与产品文案

- 最高层级按钮：`Make a new star`。
- 空状态标题：`What happened?`
- 投放区：`Drop anything, AI sorts it`。
- 状态短句示例：`AI is sorting it…`、`Added to this star`、`Couldn’t read this link. Add a note or try another source.`
- 所有主按钮使用清晰动词；尽量避免内部术语（claim、ingestion、embedding、RLS）出现在用户界面。
- 不同时展示多个视觉重量相同的主按钮。颜色与动效集中在当前主操作和当前聚焦星球。

## 8. 组件状态

每个主要组件至少设计以下状态：

- **Star**：idle、hover/focus、selected、creating、has-new-material。
- **Material**：dragging、uploading/processing、ready、failed/retry、selected。
- **Panel**：closed、opening、open。（移动端 `mobile-expanded` 属于后续版本。）
- **Drop zone**：idle、drag-over、submitting、disabled/error。
- **Generate**（后续 checkpoint）：idle、streaming、complete、error；不在 CP1 假装已有 AI。

焦点环清楚可见；禁用状态需区分于低对比装饰；加载状态避免布局跳动。

## 9. 动效与性能预算

- 3D 场景应使用 Three.js / WebGL，可用 React Three Fiber 做 React 绑定；星球少时用固定种子坐标，避免为 CP1 引入力模拟依赖。粒子尽量使用 `THREE.Points`/`BufferGeometry` 或实例化绘制，避免每个粒子单独建立 React 组件或 DOM 节点。
- 动画在渲染循环中更新；不要每帧触发 React state 更新。使用 delta time，使运动不依赖屏幕刷新率。
- 仅在用户交互或场景确实可见时运行高成本后处理；辉光可用有限强度，不以重型后处理堆叠制造效果。
- 目标：现代桌面常见设备保持稳定 50–60 fps；若掉帧，先减少 DPR、后处理和粒子数。
- 根据 `devicePixelRatio` 和视口大小动态调整并设上限；后台标签页暂停非必要循环。移动设备适配属于后续版本。
- `prefers-reduced-motion` 禁止所有持续环境运动；可提供用户可关闭动态背景的设置。
- WebGL 不可用或初始化失败时，保留 CSS 星空、DOM 经历列表和基本开面板功能；3D 是增强展示层，不得成为唯一导航。
- Next.js 中 3D 场景作为客户端组件加载；服务端首屏需有稳定背景/布局占位，避免 hydration mismatch 和闪屏。

## 10. CP1 视觉验收

1. 星图明显有 3D 深度和粒子体积感；旋转、缩放、选择均有即时反馈。
2. 星球代表经历，碎片代表素材，类型能通过颜色和图例/标签识别。
3. 新建星球、打开星球、加入碎片各自有短而克制的响应动效；空闲动画不抢注意。
4. 桌面右侧玻璃面板表现稳定，输入区域保持最突出。
5. 标题、标签、按钮由 DOM 提供；主要流程不依赖 Canvas 点击盲区或 hover。
6. 减少动态效果设置生效；无 WebGL 时仍可浏览经历。
7. UI 对照真实电脑浏览器截图检查空状态、打开面板和 reduce-motion 三个场景。
