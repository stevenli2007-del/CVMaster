# CVMaster 产品需求文档

状态：v0.1 产品基线（2026-11-24）  
MVP 决策：首版聚焦 LaTeX 简历生成；Dev post 不进入首版。

## 1. 产品愿景

CVMaster 是一个以证据为中心的求职工作台：用户随手投入链接、语音、图片、文件或文字，系统提取并整理经历事实；申请职位时，系统从已确认素材中挑选最相关内容，生成用户可以核对、编辑和导出的 LaTeX 简历。

## 2. 用户与问题

目标用户：需要反复申请实习、工作、奖学金或项目机会的学生及早期职业人士。

核心问题：经历分散在 GitHub、网页、笔记、图片和记忆中；手工整理成本高；针对每份 JD 重写简历费时；

产品原则：

- 最小化入库步骤：先收素材，系统再整理。
- 证据先于表述：所有自动整理的简历事实能回到来源。
- 用户掌控发布：生成结果必须允许审阅、编辑、删改和选择模块。
- 私密默认：素材、个人资料、职位描述和 BYOK 凭证只供该用户使用。

## 3. MVP 范围

### 3.1 账户与个人资料

- 注册、登录、登出、密码重置。
- 个人资料保存联系方式、教育背景、技能和简历偏好。
- 用户可以管理自己的 provider、API key、model、endpoint 和 protocol；CVMaster 按用户配置通过受支持的 adapter 调用，不指定唯一 provider。密钥安全实现是上线前的技术 checkpoint。

### 3.2 经历与素材库

- 一个“星球”代表一段经历、项目、实习、课程或活动；用户可只输入名称后立即开始投放素材。
- 支持粘贴网址、文本/笔记、图片、常见文档、拖放文件，以及按住说话。
- 每份素材记录来源类型、原始引用/文件、导入时间和处理状态。
- AI 从素材提取结构化事实：项目/组织、角色、行动、技术、结果、时间、技能，以及待补信息。
- 每条提取事实展示来源、置信/状态和用户确认入口；支持编辑、确认、删除。
- GitHub/Web URL 可进入抓取流程。首版仅处理公开网页，明确提示私有仓库、登录墙或抓取失败并允许用户补充文字/文件。

### 3.3 职位描述与简历生成

- 用户可粘贴职位描述；截图/OCR 属于首版候选项，若成本过高先作为后续小版本。
- AI 提取职位要求并匹配素材库中的已确认事实；匹配结果显示为什么相关以及证据来源。
- 用户选择 Education、Experience、Projects、Skills 等模块，并决定哪些经历进入当前版本。
- 输出针对该职位的 LaTeX 简历源文件；编辑内容后可再次生成。
- 生成流程不得把未确认推断写成确定事实；缺失内容显示 `[Add: ...]` 或在 UI 中标记待补充。
- PDF 导出是 MVP 的目标体验；LaTeX 编译方式须先完成技术 spike 和安全决策（见路线图）。
- 保存职位、所选素材、模块、模板版本和生成快照，支持返回修改与重新导出。

### 3.4 设计与交互

- 以提供的 deep-space prototype 为视觉方向：深色星空、弱星云、星球经历、不同颜色的素材碎片、暗色玻璃侧栏；主星图须为可实时互动的 3D 粒子场景，具体规范见 `UI.md`。
- 空状态主标题使用衬线斜体 “What happened?”；其他界面采用清晰无衬线字体。
- MVP 只做电脑端网页，使用右侧详情侧栏。移动端底部抽屉属于后续版本。开星球时聚焦它，其他星球降低亮度。
- 主要动作是 “Make a new star”；创建流程只需命名和一个大投放区。
- CP1 投放区可接收用户临时输入并以内存态显示预览碎片，清楚标注 `Preview only — not saved`；离开页面或刷新即清空，不上传、持久化、抓取网址或调用 AI。
- 动效只反馈用户操作。支持 `prefers-reduced-motion`。移动端粒子降级和触控适配不属于 MVP。
- prototype 的 “Generate a dev post” 暂不属于 MVP，可以复用已确认事实作为未来的衍生出口。

## 4. MVP 验收标准

1. 新用户能完成注册并创建一个经历，不先填写分类字段。
2. 用户添加链接、文本和至少一种文件素材后，能看到处理状态和可追溯的提取事实。
3. 用户能编辑、确认、删除提取事实，并能看到其素材来源。
4. 用户粘贴 JD 后能看到相关要求与匹配的经历证据，能选择简历模块和素材。
5. 生成结果只包含已确认事实或用户输入内容；证据缺口明确标出。
6. 用户能编辑并下载 `.tex`；如果 PDF 编译 spike 通过，则也可下载 PDF。
7. 两个账户之间不能读取对方资料、经历、素材、职位、生成结果或文件。
8. 用户能删除素材和账户；删除后的文件与派生记录按已定义保留政策处理。
9. 电脑端核心路径可通过键盘操作；减少动态效果设置生效。

## 5. 明确暂不做

- Dev post 生成、公开作品集、社交分享、团队/导师协作。
- 自动投递申请、职位爬虫、求职 CRM、支付/订阅。
- 无用户确认的自动事实补全或“自动美化”成果数据。
- 私有 GitHub 仓库授权集成（MVP 可由用户提供文件/文本替代）。

## 6. 产品度量

- 新用户首次创建 star 到成功加入第一份素材的完成率与耗时。
- 素材提取后被用户确认/编辑/拒绝的比例。
- 从粘贴 JD 到第一次生成简历的完成率与耗时。
- 生成内容中有来源支持的比例、用户删除/纠错率、标记缺口的补全率。
- 上传/AI 处理/导出失败率；账户隔离安全事件为零容忍项。

## 7. 待决事项

- BYOK 的 provider-neutral 配置与协议适配范围、密钥持久化策略、各配置的数据保留/隐私说明和密钥删除/轮换体验。
- LaTeX 编译放在自托管隔离 worker、第三方 API，还是先交付 `.tex` 并在下一 checkpoint 补 PDF。
- 图片 OCR 与截图职位描述是否纳入首发；公开 URL 的允许域名、抓取限制和 robots/版权说明。
- 首版模板（单栏/双栏、字体、页边距）及中英文简历支持范围。
- 服务地区、数据驻留、日志保留与账户删除时限。
